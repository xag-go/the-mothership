# Delegate to a helper

1. Pick the tier (see ROUTING.md):
   - checkable work (tests, exact answers, extraction, formatting, scheduling, small clear design) → cheap, medium;
   - public English writing → mid, high; data memos, partner thinking → mid, medium;
   - decisions, plans, architecture, Darija or other hard languages → top, medium (often: do it yourself);
   - never low effort for real work; no xhigh/max.
2. Large inputs: write them to a file first; pass the path, not the text.
3. Brief (templates/BRIEF.md): goal + done-criteria, exact input paths, tools allowed, tier/effort, output =
   ≤10-line summary + full result written to a path.
4. When it returns, **check it**: run the test, or spot-check 2–3 items against the source. Say what you checked.
5. Failed check on checkable work → resend one tier up (cheap → mid high → top medium). Judgment work that looks
   weak → redo at the right tier yourself; a rule check (word count, script) is not a quality check.
6. One reviewer at most, picked by the stakes; a second only on a real signal (failed test, disagreement, release).
